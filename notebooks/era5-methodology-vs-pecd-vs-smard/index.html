Own methodology vs. PECD (multi-year, ERA5-driven)¶

Does this hub’s own from-scratch capacity-factor chain (GWA wind-speed bias correction, hub-height extrapolation, per-plant turbine curves, PECD-documented solar chain -- edh.forecast_capacity_factors, the same code energy-data-hub’s WeatherNext asset uses, just fed era5_grid’s real reanalysis instead of a forecast) track PECD’s own official capacity-factor product, over several years? Deliberately fed real historical weather, never a forecast -- isolates the weather-to-power conversion methodology from any forecast-model-skill question, unlike 16_weathernext_forecast_vs_pecd.py.

Both sides use today’s real, pinned MaStR fleet held fixed across the whole historical window (the hub’s established “current fleet” convention -- see edh.forecast_capacity_factors’s own module docstring), not a historically-accurate per-year fleet. That’s fine for this comparison -- own-methodology and PECD both use the exact same (today’s) fleet weights, so the fleet choice cancels out and doesn’t bias the comparison either way.

Not yet included here: PECD vs. real SMARD generation. That comparison needs the fleet’s actual, historically-accurate size at each past date (SMARD’s real generation reflects whatever fleet existed in e.g. 2019, not today’s much larger one) -- mixing in today’s fixed fleet would conflate “does PECD’s weather-to-power conversion match reality” with “how much has the fleet grown since”, which isn’t a clean question. The hub already has the right building block for this, unused so far: edh.pecd’s “historic” weighting variant (capacity_monthly_panel -> compute_potential_monthly, each hour weighted by that calendar month’s actual installed capacity -- see that module’s docstring) instead of the “current fleet” variant used here. Left for a follow-up once this first comparison looks sound.

Window: every month with both ERA5 and PECD on disk -- currently 2018-10 through 2025-12 (PECD’s own official product stops at 2025; see edh.pecd.YEARS). The own-methodology chain is computed once per month by edh.forecast_capacity_factors.compute_and_save_month (a disk-cached step, not re-run by this notebook -- see that function’s own docstring) and read back here.

Today’s real fleet, as the fixed weighting basis for every series here¶

Same “current pinned snapshot” convention as 16_weathernext_forecast_vs_ pecd.py -- expand_wind_zone_weights (wind, PEON/PEOF zones) and a straight per-(region, technology) capacity grouping (solar), both already-validated hub functions, reused as-is.

as_of = pd.Timestamp.now().normalize()
onshore, offshore = active_wind_plants(as_of)
configs = active_solar_configs(as_of)
cap_onshore, cap_offshore, cap_pv = onshore["capacity_mw"].sum(), offshore["capacity_mw"].sum(), configs["capacity_mw"].sum()
cap_total = cap_onshore + cap_offshore + cap_pv
print(f"Today's fleet (MW): onshore={cap_onshore:,.0f}  offshore={cap_offshore:,.0f}  pv={cap_pv:,.0f}  total={cap_total:,.0f}")

onshore_weights = expand_wind_zone_weights(onshore, pecd_mask_file("peon")).groupby("zone_id")["capacity_mw"].sum()
offshore_weights = expand_wind_zone_weights(offshore, pecd_mask_file("peof")).groupby("zone_id")["capacity_mw"].sum()
solar_weights = configs.groupby(["nuts2_region", "pecd_technology"])["capacity_mw"].sum()


def blend_pecd_to_national(wind_onshore_de: pd.DataFrame, wind_offshore_de: pd.DataFrame, solar_de_by_tech: dict) -> pd.DataFrame:
    """PECD's own zone/region-columned product, blended to one Germany
    number per technology + a capacity-weighted `full_re` blend, using
    today's real fleet weights -- identical approach to
    `16_weathernext_forecast_vs_pecd.py::blend_to_national`."""
    common_on = [z for z in onshore_weights.index if z in wind_onshore_de.columns]
    w_on = onshore_weights[common_on] / onshore_weights[common_on].sum()
    cf_onshore = (wind_onshore_de[common_on] * w_on).sum(axis=1)

    common_off = [z for z in offshore_weights.index if z in wind_offshore_de.columns]
    w_off = offshore_weights[common_off] / offshore_weights[common_off].sum()
    cf_offshore = (wind_offshore_de[common_off] * w_off).sum(axis=1)

    cf_pv = pd.Series(0.0, index=solar_de_by_tech["60"].index)
    weight_total = 0.0
    for (region, tech), weight in solar_weights.items():
        if region in solar_de_by_tech[tech].columns:
            cf_pv = cf_pv.add(solar_de_by_tech[tech][region] * weight, fill_value=0)
            weight_total += weight
    cf_pv = cf_pv / weight_total
    cf_pv.index = cf_pv.index - pd.Timedelta(hours=1)  # PECD's documented solar-only 1h timestamp shift

    full_re = (cf_pv * cap_pv + cf_onshore * cap_onshore + cf_offshore * cap_offshore) / cap_total
    return pd.DataFrame({"pv": cf_pv, "wind_onshore": cf_onshore, "wind_offshore": cf_offshore, "full_re": full_re}).dropna(how="all")

Own methodology, fed ERA5 -- every month already computed and cached¶

Reads era5_capacity_factors_month_file’s output directly (written by edh.forecast_capacity_factors.compute_and_save_month, run once ahead of time as a backfill over every era5_grid month on disk -- not recomputed here, same reasoning as forecast_capacity_factors_de’s own per-day cache: the full chain costs real per-month compute time, not something a notebook re-execution should redo).

cf_dir = HUB_DATA / "era5_capacity_factors"

Metrics: own methodology vs. PECD, at every aggregation level, CF and MW¶

The same correlation/MAE/NMAE/bias as before, but now at six aggregation levels (hourly through monthly -- each level resamples both series to that frequency’s mean before comparing, so e.g. “daily” compares daily-mean capacity factors, not hourly values within a day) and in two units: the normalized capacity factor used everywhere else on this page, and the real power (MW) it implies against today’s fixed fleet capacity for that technology -- same capacity used throughout this page, so the MW metrics are a rescaling of the CF ones, not an independent measurement. CF alone makes cross-technology comparison easy (solar/wind onshore/offshore are all 0-1); MW puts the error back in context of each technology’s actual real-world scale (wind offshore’s smaller fleet means its CF errors matter less in MW terms than onshore’s, even where NMAE looks similar).

AGG_FREQS = [("1h", "Hourly"), ("2h", "2-hourly"), ("1D", "Daily"), ("1W", "Weekly"), ("1MS", "Monthly")]
TECH_CAPACITY_MW = {"pv": cap_pv, "wind_onshore": cap_onshore, "wind_offshore": cap_offshore, "full_re": cap_total}


def compare(a: pd.Series, b: pd.Series) -> dict:
    joined = pd.DataFrame({"a": a, "b": b}).dropna()
    err = joined["a"] - joined["b"]
    return {
        "n": len(joined),
        "corr": joined["a"].corr(joined["b"]),
        "mae": err.abs().mean(),
        "nmae": err.abs().mean() / joined["b"].mean(),
        "bias": err.mean(),
    }


own_h = own.loc[overlap_start:overlap_end]
pecd_h = pecd.loc[overlap_start:overlap_end]

rows = []
for tech in TECHS:
    cap_mw = TECH_CAPACITY_MW[tech]
    for freq, freq_label in AGG_FREQS:
        own_r = own_h[tech].resample(freq).mean()
        pecd_r = pecd_h[tech].resample(freq).mean()
        rows.append({"technology": TECH_LABELS[tech], "aggregation": freq_label, "unit": "capacity factor", **compare(own_r, pecd_r)})
        rows.append({"technology": TECH_LABELS[tech], "aggregation": freq_label, "unit": "MW", **compare(own_r * cap_mw, pecd_r * cap_mw)})

metrics = pd.DataFrame(rows).set_index(["technology", "aggregation", "unit"]).round(4)

Seasonality of the methodology gap: year x month MAE heatmap¶

Mean absolute error (capacity-factor units, own methodology vs. PECD), one cell per (year, calendar month) -- computed from the native hourly errors within that month, not the monthly-mean series (a monthly mean of errors can cancel out through the month; this is the mean of |hourly error|, so it reflects genuine within-month mismatch, not just a shifted monthly average). Sequential, single-hue (blue), light=low error -> dark=high error, one hue ramp per the project’s own palette (references/palette.md’s sequential blue steps), each panel scaled to its own technology’s error range since solar/wind magnitudes differ structurally.

from matplotlib.colors import LinearSegmentedColormap

MAE_CMAP = LinearSegmentedColormap.from_list(
    "mae_blue",
    ["#cde2fb", "#9ec5f4", "#6da7ec", "#3987e5", "#256abf", "#184f95", "#0d366b"],
)
MONTH_LABELS = ["Jan", "Feb", "Mar", "Apr", "May", "Jun", "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"]

err_h = (own_h - pecd_h).abs()
err_h["year"] = err_h.index.year
err_h["month"] = err_h.index.month

fig, axes = plt.subplots(2, 2, figsize=(12, 8.5), dpi=130)
fig.patch.set_facecolor(SURFACE)
for ax, tech in zip(axes.flat, TECHS):
    ax.set_facecolor(SURFACE)
    pivot = err_h.groupby(["year", "month"])[tech].mean().unstack("month").reindex(columns=range(1, 13))
    im = ax.pcolormesh(pivot.values, cmap=MAE_CMAP, edgecolors=SURFACE, linewidth=1.5)
    ax.set_xticks(np.arange(12) + 0.5)
    ax.set_xticklabels(MONTH_LABELS, fontsize=7.5, color=TEXT_SECONDARY)
    ax.set_yticks(np.arange(len(pivot.index)) + 0.5)
    ax.set_yticklabels(pivot.index, fontsize=7.5, color=TEXT_SECONDARY)
    ax.invert_yaxis()
    ax.set_title(TECH_LABELS[tech], color=TEXT_PRIMARY, fontsize=11.5, loc="left")
    for spine in ax.spines.values():
        spine.set_visible(False)
    cbar = fig.colorbar(im, ax=ax, fraction=0.046, pad=0.03)
    cbar.ax.tick_params(labelsize=7, colors=TEXT_SECONDARY)
    cbar.outline.set_visible(False)
fig.suptitle("MAE by calendar month and year: own methodology vs. PECD (capacity-factor units)", color=TEXT_PRIMARY, fontsize=12.5, x=0.02, ha="left", y=0.995)
fig.tight_layout(rect=[0.0, 0.0, 1, 0.96])
